# DEPLOY-001 — ограничения

- DNS: отсутствует делегирование school-events.ru в .ru; публичный HTTPS и браузерный маршрут через домен пока не проверены.
- Фактическая Ubuntu 22.04.5 отличается от 24.04 в задании. Major upgrade не проводился.
- Nuxt использует hybrid rendering: /login и /forgot-password SSR; страницы кабинета сохраняют клиентский рендеринг из существующей архитектуры API plugin. Это не полное SSR всего кабинета.
- Первоначальный режим только MockProvider. Демонстрации и Test Sign-Off не являются реальной генерацией LLM или педагогической экспертизой.
- Бэкапы находятся на том же VPS. Потеря диска/сервера уничтожит и их; требуется внешняя зашифрованная копия. Автоматическое удаление/retention не включено, нужно контролировать место на диске.
- Согласованность pg_dump обеспечивается PostgreSQL; архив экспортов не является атомарным snapshot с БД при параллельной пользовательской работе. Перед восстановлением проверять состав.
- Rollback образов не откатывает миграции. Несовместимые schema changes требуют отдельного плана.
- Первый и повторный production deploy используют одну проверенную пару SHA. Процедура rollback подготовлена; переход на другую production-версию пока не испытан.
- Production smoke выполнен на VPS через SSH/loopback. Проверка публичного браузерного маршрута, TLS-сертификата и поведения cookies по реальному HTTPS остаётся до исправления DNS.
- Deployment останавливает worker до backup/migration, но не реализует полноценный zero downtime и автоматический rollback при отказе.
- Firewall провайдера не проверен через его панель. Применён локальный UFW; наружу Docker публикует только 80/443, диагностика 8080 привязана к loopback.
- Registry read tokens истекают 08.11.2027; CI SSH и registry credentials требуют плановой ротации.
- Scheduler не добавлен: routes/console.php не содержит необходимых приложению scheduled tasks.
